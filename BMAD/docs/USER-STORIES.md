- 對應：NFR-01｜—｜用例 —｜原 US（PRD）：—

## E2 帳號

### E2-S1 註冊帳號（P0）

身為**訪客**，我想要用 email 與密碼註冊，以便我可以使用預約功能。

- 對應：FR-01｜BR-22、23、24｜用例 UC-01｜原 US（PRD）：US-12
- 驗收條件：
  - Given 訪客輸入未使用的 email 與符合規則的密碼（至少 8 碼且含英文與數字），When 送出，Then 建立帳號、寄出驗證信並自動登入。
  - Given 密碼不符規則，When 送出，Then 回傳 `PASSWORD_TOO_WEAK` 並說明規則，不建立帳號。
  - Given email 屬於只用 Google 登入的帳號，When 送出，Then 不建立新帳號、改寄「設定密碼」信，畫面只顯示「請查收信件」，不透露帳號是否存在。

### E2-S2 驗證 email（P0）

身為**會員**，我想要點擊信中連結驗證 email，以便我可以新增預約、付款與改期。

- 對應：FR-02｜BR-05、23｜用例 UC-02｜原 US（PRD）：US-13
- 驗收條件：
  - Given 有效的驗證連結（24 小時內、未使用），When 點擊，Then 寫入 email 驗證時間，之後可預約。
  - Given 連結過期或已使用，When 點擊，Then 顯示錯誤並可輸入 email 重寄，不論 email 是否存在都顯示相同訊息。
  - Given 會員未驗證 email，When 進入預約頁，Then 看到驗證提示，且建立訂單被拒（`EMAIL_NOT_VERIFIED`）。

### E2-S3 登入與登出（P0）

身為**會員**，我想要以 email 與密碼登入、登出，以便安全地使用我的帳號。

- 對應：FR-03｜BR-21、22｜用例 UC-03｜原 US（PRD）：US-14
- 驗收條件：
  - Given 帳號密碼正確，When 登入，Then 更新最後登入時間並歸零失敗次數。
  - Given 帳號或密碼錯誤，When 登入，Then 統一顯示「帳號或密碼錯誤」。
  - Given 連續失敗 5 次，Then 鎖定 15 分鐘並顯示剩餘時間（`ACCOUNT_LOCKED`）。
  - Given 帳號為 FROZEN 或 BLACKLISTED，When 登入，Then 可登入查看與取消既有訂單，但不能新預約、付款或改期。

### E2-S4 Google 登入（P0（mock）、P1（真實憑證））

身為**訪客**，我想要使用 Google 帳號登入，以便不用另外記密碼。

- 對應：FR-04｜BR-24｜用例 UC-04｜原 US（PRD）：US-15
- 驗收條件：
  - Given Google 身分已綁定帳號，When 登入，Then 直接登入。
  - Given 沒有綁定且 email 不存在，When 登入，Then 建立帳號並綁定，Google 已驗證的 email 視為已驗證。
  - Given 沒有綁定但 email 已存在，When 登入，Then 不自動合併，導向「確認綁定」頁，輸入該帳號密碼正確後才綁定並登入。
  - Given 該帳號已綁定另一個 Google 帳號，Then 回傳 `ACCOUNT_ALREADY_LINKED`，提示改用原本的 Google 帳號。

### E2-S5 忘記密碼（P0）

身為**會員**，我想要以 email 重設密碼，以便忘記密碼時仍能登入。

- 對應：FR-05｜BR-22、23｜用例 UC-05｜原 US（PRD）：US-19
- 驗收條件：
  - Given 任一 email，When 申請重設，Then 一律顯示相同訊息（不洩漏帳號是否存在）。
  - Given 有效重設連結（30 分鐘內、單次使用），When 設定新密碼，Then 該使用者所有重設權杖失效、鎖定解除。

### E2-S6 設定本地密碼（P0）

身為**只用 Google 登入的會員**，我想要設定一組本地密碼，以便也能用 email 與密碼登入同一帳號。

- 對應：FR-06｜BR-22、23｜用例 UC-06｜原 US（PRD）：US-21

  - Given 設定完成，When 以 email 與新密碼登入，Then 登入同一帳號。

### E2-S7 修改個人資料（P0）

身為**會員**，我想要修改姓名與電話，以便資料保持正確。

- 對應：FR-07｜—｜用例 UC-07｜原 US（PRD）：US-17
- 驗收條件：
  - Given 已登入，When 修改姓名或電話，Then 儲存成功；email 欄位不可修改。

### E2-S8 變更密碼（P0）

身為**會員**，我想要輸入舊密碼後變更密碼，以便保護帳號安全。

- 對應：FR-08｜BR-22｜用例 UC-07｜原 US（PRD）：US-18
- 驗收條件：
  - Given 舊密碼正確且新密碼符合規則，When 變更，Then 成功。
  - Given 舊密碼錯誤，Then 回傳 `INVALID_CREDENTIALS`。
  - Given 只用 Google 登入者，Then 顯示「設定密碼」入口而非「變更密碼」。

## E3 場館與空間管理

### E3-S1 管理場館（P0）

身為**管理員**，我想要新增、修改、停用與啟用場館，以便維護可供租借的據點。

- 對應：FR-40｜BR-18｜用例 UC-20｜原 US（PRD）：US-49
- 驗收條件：
  - Given 管理員，When 新增或修改場館（地址、電話、經緯度、整點營業時間），Then 儲存成功。
  - Given 場館有未來的待付款或已確認訂單，When 停用，Then 畫面列出受影響訂單供逐筆處理，且該場館空間不再被搜尋或新預約。
  - Given 非管理員，When 呼叫後台 API，Then 回傳 `FORBIDDEN`。

### E3-S2 管理空間（P0）

身為**管理員**，我想要新增、修改空間並切換狀態（可預約、維修中、停用），以便控制哪些空間可被預約。

- 對應：FR-41｜BR-18｜用例 UC-21｜原 US（PRD）：US-50、51、56
- 驗收條件：
  - Given 管理員修改空間時租，Then 既有訂單金額不受影響（時租快照）。
  - Given 空間改為維修中或停用，Then 不再出現在搜尋、不能新預約，待付款訂單也不能付款，並列出受影響訂單。

### E3-S3 管理空間照片（P0）

身為**管理員**，我想要上傳、刪除、排序照片並設定封面，以便讓使用者看到空間實況。

- 對應：FR-42｜—｜用例 UC-22｜原 US（PRD）：US-52
- 驗收條件：
  - Given jpg、png、webp 且 ≤ 5 MB 的檔案，When 上傳，Then 成功並以 UUID 重新命名。
  - Given 格式或大小不符，Then 回傳 `INVALID_UPLOAD`。
  - Given 已上傳多張照片，When 拖曳排序，Then 第一張為封面。

### E3-S4 管理設備（P0）

身為**管理員**，我想要維護設備清單並設定各空間的設備、數量與規格，以便讓使用者能依設備篩選空間。

- 對應：FR-43｜—｜用例 UC-23｜原 US（PRD）：US-53
- 驗收條件：
  - Given 設備清單，When 新增或停用設備，Then 停用後不出現在篩選與設定選單。
  - Given 某空間，When 整批設定設備（數量、規格如「75 吋」），Then 空間詳細頁顯示。

## E4 搜尋與空間

### E4-S1 搜尋空間（P0）

身為**訪客**，我想要依縣市、行政區、人數、價格、類型、設備與日期時段搜尋，以便快速找到合適的空間。

- 對應：FR-10｜BR-04｜用例 UC-08｜原 US（PRD）：US-01～06
- 驗收條件：
  - Given 設定條件，When 搜尋，Then 只顯示 AVAILABLE 空間與 OPEN 場館，容量 ≥ 人數、設備須全部具備、指定時段須可預約，每頁 12 筆。
  - Given 沒有符合結果，Then 顯示空狀態並建議放寬條件。

### E4-S2 定位搜尋附近（P0）

身為**訪客**，我想要授權定位後看附近空間，以便找離我最近的空間。

- 對應：FR-11｜—｜用例 UC-09｜原 US（PRD）：專案討論
- 驗收條件：
  - Given 使用者授權定位，Then 顯示 5 公里內空間並依距離排序、顯示距離。
  - Given 拒絕或定位失敗，Then 提示並保留手動搜尋。

### E4-S3 搜尋結果排序（P1）

身為**訪客**，我想要依價格、容量或距離排序，以便比較空間。

- 對應：FR-12｜—｜用例 UC-08｜原 US（PRD）：US-10

### E4-S4 查看空間詳細（P0）

身為**訪客**，我想要看照片、介紹、設備、規定、取消規則、地址與評論，以便決定是否預約。

- 對應：FR-13｜—｜用例 UC-10｜原 US（PRD）：US-07～09

  - Given 評論被管理員隱藏，Then 不顯示。

### E4-S5 查看可預約時段（P0）

身為**訪客**，我想要選日期後看每個整點時段的狀態，以便知道哪些時段可預約。

  - Given 待付款訂單已逾時但排程尚未處理，Then 該時段顯示為可預約。

### E4-S6 收藏空間（P0）

## E5 預約與付款

### E5-S1 預約前確認（P0）

身為**會員**，我想要選好時段後確認時數、時租、總金額、付款期限與取消規則，以便清楚知道要付多少與如何取消。

- 對應：FR-20｜BR-07｜用例 UC-13｜原 US（PRD）：US-26～28
- 驗收條件：
  - Given 選定連續時段並填使用人數與備註，Then 顯示由後端試算的金額（前端不自行計算）與取消規則。
  - Given 人數超過容量，Then 回傳 `OVER_CAPACITY`。

### E5-S2 建立訂單（P0）

身為**會員**，我想要送出預約並保留時段 15 分鐘，以便在付款期間不被他人搶走。

- 對應：FR-21｜BR-01～08｜用例 UC-13｜原 US（PRD）：US-29～31
- 驗收條件：
  - Given 符合 BR-01～06，When 送出，Then 建立待付款訂單並顯示付款倒數。
  - Given 時段已被他人預約，Then 回傳 `SLOT_TAKEN` 並刷新時段。
  - Given 已有 3 筆待付款，Then 回傳 `PENDING_LIMIT`。
  - Given 20 個併發請求預約同一時段，Then 只成立 1 筆（使用實際 PostgreSQL 測試）。

### E5-S3 模擬付款（P0）

身為**會員**，我想要以信用卡或 LINE Pay 付款，以便取得預約。

- 對應：FR-22｜BR-08、09、10、18｜用例 UC-14｜原 US（PRD）：US-33～36
- 驗收條件：
  - Given 期限內付款成功，Then 訂單轉已確認並產生房間密碼。
  - Given 使用測試卡號 `4000 0000 0000 0002`，Then 顯示「卡片遭拒」，訂單維持待付款，期限內可重付。
  - Given 重複點擊（同一冪等鍵），Then 回傳原結果，不重複扣款。
  - Given 已超過期限，Then 顯示「訂單已失效」（`BOOKING_EXPIRED`）；空間或場館已停用，則顯示無法付款。

### E5-S4 確認信與房間密碼（P0）

身為**會員**，我想要付款後收到含房間密碼與入場資訊的確認信，以便到場能自助入場。

- 對應：FR-23｜BR-10、11、26｜用例 UC-14、15｜原 US（PRD）：US-42～44、47

  - Given 郵件伺服器故障，Then 訂單仍成功，通知紀錄為失敗且可重試。

## E6 我的訂單

  - Given 已登入，Then 各分頁籤顯示編號、空間、時段、金額、狀態，且只含本人訂單。

### E6-S2 訂單詳細與房間密碼（P0）

身為**會員**，我想要查看付款與退款紀錄、取消規則與房間密碼狀態，以便到場時知道如何入場。

- 對應：FR-31｜BR-11｜用例 UC-15、16｜原 US（PRD）：US-38、43～45
- 驗收條件：

  - Given 訂單不屬於本人，Then 回傳 `NOT_FOUND`。

### E6-S3 取消訂單並退款（P0）

身為**會員**，我想要取消訂單並依規則退款，以便行程改變時降低損失。

- 對應：FR-32｜BR-12、25、26｜用例 UC-17｜原 US（PRD）：US-39、40、46
- 驗收條件：
  - Given 已確認訂單，When 取消前，Then 顯示預計退款金額與比例（≥24 小時 100%、3～24 小時 50%、不到 3 小時 0%）。
  - Given 確認取消，Then 退款、撤銷房間密碼、寄送通知；重複送出不重複退款。
  - Given 待付款訂單取消，Then 不涉及退款。
  - Given 訂單已完成或時段已結束，Then 回傳 `INVALID_STATE`。

### E6-S4 改期（P0）

身為**會員**，我想要把已確認訂單改到另一個時段，以便行程改變時不必取消重訂。

- 對應：FR-33｜BR-14、25、26｜用例 UC-18｜原 US（PRD）：US-41
- 驗收條件：
  - Given 已確認、原開始時間 ≥ 24 小時後、未改期過，When 選新時段，Then 顯示價差；改貴須補付（模擬付款成功才生效），改便宜退差額。
  - Given 補付卡片遭拒或新時段被他人預約，Then 整個操作回滾，原訂單不變。
  - Given 不符改期條件，Then 回傳 `RESCHEDULE_NOT_ALLOWED`。

### E6-S5 撰寫評論（P0）

身為**會員**，我想要對已完成的訂單評分並留言，以便幫助其他使用者並回饋空間。

- 對應：FR-34｜BR-16｜用例 UC-19｜原 US（PRD）：專案討論
- 驗收條件：
  - Given 本人已完成的訂單，且在 end_at 起 30 天內、尚未評論，When 送出評分（1–5），Then 顯示在空間詳細頁。
  - Given 不符條件，Then 回傳 `REVIEW_NOT_ALLOWED`。

## E7 管理員訂單、會員與評論

### E7-S1 查詢訂單（P0）

身為**管理員**，我想要依編號、會員 email、空間、日期區間與狀態查詢訂單，以便快速找到並處理客戶訂單。

- 對應：FR-44｜BR-25｜用例 UC-24｜原 US（PRD）：US-59、60、63、64
- 驗收條件：
  - Given 查詢條件，Then 回傳符合的訂單；詳細頁含付款與退款、狀態紀錄、房間密碼狀態與通知紀錄。

### E7-S2 取消與代為改期（P0）

身為**管理員**，我想要因場地因素取消訂單或代為改期，以便妥善處理受影響的客戶。

- 對應：FR-45｜BR-13、19｜用例 UC-25、26｜原 US（PRD）：US-61、62、65
- 驗收條件：
  - Given 管理員取消訂單並填寫原因，Then 已付款者全額退款、撤銷房間密碼、寄送通知。
  - Given 管理員代為改期且時數與原訂單相同，Then 金額不變、無補付或退款、不計入改期次數。
  - Given 時數不同或未填原因，Then 被拒絕；管理員不能直接修改金額或狀態。

### E7-S3 部分退款（P1）

身為**管理員**，我想要對成功付款申請部分退款，以便處理客訴或補償。

- 對應：FR-45｜BR-17｜用例 UC-27｜原 US（PRD）：US-61、62、65
- 驗收條件：
  - Given 退款金額 ≤ 淨實收，When 送出（帶冪等鍵），Then 新增退款紀錄、訂單狀態不變、寫入狀態紀錄；重複送出不重複退款。
  - Given 退款總額會超過實收，Then 回傳 `REFUND_EXCEEDS_PAID`。

### E7-S4 管理會員（P0）

身為**管理員**，我想要依 email、姓名、狀態查詢會員並凍結、列入黑名單、解除，以便處理違規或久未使用的帳號。

- 對應：FR-46｜BR-20、21｜用例 UC-28｜原 US（PRD）：US-67
- 驗收條件：
  - Given 凍結或黑名單，When 未填原因，Then 被拒絕；填寫後該會員不能新預約、付款、改期，但可取消。
  - Given 解除，Then 帳號回到 ACTIVE 並清除原因。

### E7-S5 管理評論（P0）

身為**管理員**，我想要隱藏或取消隱藏評論，以便維持評論內容品質。

- 對應：FR-47｜—｜用例 UC-29｜原 US（PRD）：專案討論
- 驗收條件：
  - Given 評論列表，When 隱藏，Then 公開頁不再顯示；取消隱藏後恢復。

### E7-S6 通知紀錄與重試（P1）

身為**管理員**，我想要查看通知寄送結果並重試失敗者，以便確保客戶收到訂單通知。

- 對應：FR-48｜BR-26｜用例 UC-30｜原 US（PRD）：US-66
- 驗收條件：
  - Given 通知紀錄，When 依狀態查詢，Then 可看到失敗者並手動重試。
  - Given 驗證、重設、設定密碼信（含單次權杖），Then 不提供重試，需使用者重新申請。

## E8 排程

### E8-S1 逾時待付款轉失效（P0）

身為**系統**，我想要每分鐘將逾時的待付款訂單轉為已失效，以便釋出被佔用的時段。

- 對應：FR-50｜BR-08｜用例 UC-31｜原 US（PRD）：—
- 驗收條件：
  - Given 待付款訂單超過 15 分鐘，When 排程執行，Then 轉 EXPIRED 並寫狀態紀錄；重複執行結果不變。
  - Given 付款與排程同時處理同一訂單，Then 先取得鎖的一方生效。

### E8-S2 自動完成訂單（P0）

身為**系統**，我想要每 5 分鐘將結束的已確認訂單轉為已完成，以便讓會員能撰寫評論。

- 對應：FR-51｜BR-15｜用例 UC-31｜原 US（PRD）：—
- 驗收條件：
  - Given 已確認訂單的結束時間已到，When 排程執行，Then 轉 COMPLETED。

### E8-S3 清理過期資料（P0）

身為**系統**，我想要每日刪除過期的房間密碼與帳號權杖，以便降低敏感資料的保存時間。

- 對應：FR-52、FR-53｜BR-11｜用例 UC-31｜原 US（PRD）：—
- 驗收條件：
  - Given valid_until 超過 7 天的房間密碼，或過期／已使用超過 7 天的權杖，When 排程執行，Then 刪除；重複執行結果不變。

### E8-S4 久未登入自動凍結（P1）

身為**系統**，我想要每日凍結 180 天未登入的會員，以便降低閒置帳號風險。

- 對應：FR-54｜BR-21｜用例 UC-31｜原 US（PRD）：—
- 驗收條件：
  - Given USER 且 ACTIVE、最後登入（無則建立時間）超過 180 天，When 排程執行，Then 凍結並寫入原因「久未登入」；管理員帳號不受影響。

### E8-S5 失敗通知重試（P1）

身為**系統**，我想要每 10 分鐘重試寄送失敗的通知，以便降低漏信機率。

- 對應：FR-55｜BR-26｜用例 UC-31｜原 US（PRD）：—
- 驗收條件：
  - Given 失敗且嘗試少於 3 次的通知，When 排程執行，Then 重試；以 `SKIP LOCKED` 避免重複寄送。
